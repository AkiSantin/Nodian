# Nodian

YAML frontmatter の双方向リレーションを自動同期する [Obsidian](https://obsidian.md) プラグインです。

あるファイルのプロパティに wikilink を追加すると、プラグインがターゲットファイルの対応プロパティにバックリンクを自動で書き込みます。リンクを削除すると、バックリンクも自動で削除されます。

![Nodian の概要](https://github.com/user-attachments/assets/11ad508d-7dd8-4a9b-8395-b17fd1f3ff21)


## 例

```
Person.md                          Mail.md
─────────                          ─────────
tags: [Person]                     tags: [Mail]
Mail: [[hello@example]]     →     Person: [[Alice]]        ← 自動生成
```

## 機能

- **自動同期** — 一方のファイルでリンクを追加・削除すると、もう一方が即座に更新
- **リレーションペア** — どのプロパティがペアかを定義（例：`Mail ↔ Person`、`Artist ↔ Songs`）
- **タグベースのマッチング** — 各ペアにはタグが必須。プロパティとタグの両方が一致した場合のみ同期
- **表示名** — オプションで `title` プロパティをバックリンクの表示テキストとして使用
- **新規ファイル対応** — wikilink からファイルを作成すると、タグとバックリンクを自動追加
- **フル同期** — リボンアイコン・設定・コマンドパレットのどこからでもワンクリックで実行
- **多言語対応** — 英語、日本語、繁体字中国語
- **モバイル対応** — スマートフォンではカード型のペア管理 UI を提供

## インストール

### BRAT を使用（推奨）

1. Community Plugins から [BRAT](https://github.com/TfTHacker/obsidian42-brat) をインストール
2. BRAT → Add Beta Plugin → `AkiSantin/Nodian`

### 手動インストール

`main.js`、`manifest.json`、`styles.css` を以下にコピー：

```
<vault>/.obsidian/plugins/nodian/
```

Obsidian を再起動 → 設定 → Community Plugins → Nodian を有効化。

## はじめに

### ステップ 1：最初のペアを作成

任意の `.md` ファイルを開き、YAML プロパティに wikilink を追加します：

```yaml
---
tags: [Person]
Mail: "[[hello@example]]"
---
```

プロパティ名を右クリック → **双方向リレーションを設定** を選択。

モーダルで対応プロパティ（例：`Person`）とタグを設定し、**保存** を押します。

### ステップ 2：確認

`hello@example.md` を開くと、以下が表示されるはずです：

```yaml
---
tags: [Mail]
Person: "[[Alice]]"
---
```

これで完了です。以降、すべてのファイルの `Mail` プロパティがターゲットファイルの `Person` プロパティと自動同期されます。

### ステップ 3：フル同期（既存の保管庫）

保管庫に既存のリレーションがある場合、以下のいずれかの方法で一度フル同期を実行します：

- 左側リボンの**同期アイコン**をクリック
- 設定 → Nodian → **フル同期を実行**
- コマンドパレット（`Cmd/Ctrl+P`）→ **すべての双方向リレーションを同期**

すべてのファイルをスキャンし、不足しているバックリンクを補完します。

## 使い方

### リンクの追加

ペア設定済みのプロパティに wikilink を追加すると、ターゲットファイルにバックリンクが自動で書き込まれます。

```yaml
# Artist.md に入力：
Songs: "[[Blue Sky]]"

# プラグインが Blue Sky.md に自動生成：
Artist: "[[Artist Name]]"
```

### リンクの削除

プロパティから wikilink を削除すると、ターゲットファイルのバックリンクも自動で削除されます。

### 複数リンク

プロパティには複数の wikilink を含めることができます：

```yaml
Songs:
  - "[[Blue Sky]]"
  - "[[Red Moon]]"
  - "[[Green Field]]"
```

各ターゲットファイルにそれぞれバックリンクが作成されます。1つのリンクを削除しても、そのターゲットのみに影響します。

### セルフリレーション

プロパティは自分自身とペアにすることもできます：

```
Related ↔ Related
```

A.md に `Related: [[B]]` を追加すると、B.md に `Related: [[A]]` が自動で追加されます。

### 表示名

デフォルトでは、バックリンクはファイル名のみを使用します：`[[my-artist-id]]`。

`title` プロパティを表示テキストとして使うには、設定で **title を表示名として使用** を有効にしてください。バックリンクは `[[my-artist-id|Some Artist Name]]` のように表示されます（ソースファイルの `title` frontmatter プロパティの値を使用）。`title` プロパティのみが使用されます — `aliases` は参照されません。

この設定を切り替えても、既存のバックリンクは自動更新されません。変更後はフル同期を実行して、保管庫全体のバックリンクを更新してください。

### 新規ファイルの作成

まだ存在しないファイルにリンクした場合：

```yaml
Mail: "[[new-contact]]"
```

`new-contact.md` が作成されると（例：Obsidian でリンクをクリック）、プラグインが：
1. 新しいファイルに適切なタグを自動追加
2. バックリンクを自動で書き込み

### モバイルでの利用

スマートフォンでは、Nodian はネイティブ風のカード UI を使用します：

- プロパティアイコンをタップ → **双方向リレーション設定** 画面に、適用中のペアとそのプロパティの既存ペアがカードで表示されます
- **＋** ボタンで専用の追加画面が開き、タグ・プロパティの入力には自動補完が使えます
- 設定 → **リレーションペア** も同じカード表示になり、編集・削除ができます

デスクトップのレイアウトは変わりません。

## タグ

すべてのリレーションペアには 2 つのタグ — **タグ A** と **タグ B** — があり、プロパティ A とプロパティ B に対応します。タグは**必須**であり、省略できません。

### タグの仕組み

プラグインは以下の **両方の条件** が満たされた場合にのみ同期します：

1. ソースファイルにペアのプロパティ名と一致するプロパティがある
2. ソースファイルのタグがそのペアの対応するタグと一致する

これにより、誤ったターゲットへの同期を防ぎます。例えば、`Release` ファイルと `Song` ファイルの両方に `Artist` プロパティがある場合、タグによって各ペアが正しいファイルタイプでのみ動作します — `Release` タグのファイルは `Artist ↔ Release` ペアを使用し、`Song` タグのファイルは `Artist ↔ Song` ペアを使用します。

### タグの自動割り当て

- メニューからペアを作成する際、ソースファイルのタグが自動的に使用されます。
- wikilink から新規ファイルが作成される際、プラグインはペア定義から適切なタグを自動で割り当てます。

## 設定

設定 → Nodian を開きます。

### リレーションペア

プロパティペアの追加・編集・削除。各ペアは 2 つのプロパティ名と 2 つのタグを定義し、双方向にリンクされます。

| 設定 | デフォルト | 説明 |
|------|-----------|------|
| 自動同期 | オン | 編集時にバックリンクを自動同期 |
| title を表示名として使用 | オフ | バックリンクに `title` プロパティを表示テキストとして使用。変更後はフル同期を実行してください。 |
| リボン同期ボタンを表示 | オン | 左側のリボンにフル同期ボタンを表示 |
| デバッグモード | オフ | 開発者コンソールに詳細ログを出力（`Cmd/Ctrl+Option+I`、`[YBR]` でフィルタ） |

## ペアの例

各ペアには設定でタグ A とタグ B も設定されます。以下の表はプロパティのペアのみを表示しています — タグはペア作成時に設定またはメニューから指定します。

音楽の保管庫：

| プロパティ A | ↔ | プロパティ B |
|-------------|---|-------------|
| Artist | ↔ | Release |
| Artist | ↔ | Tracks |
| Composer | ↔ | Works |
| Label | ↔ | Releases |
| Related | ↔ | Related |

企業/CRM の保管庫：

| プロパティ A | ↔ | プロパティ B |
|-------------|---|-------------|
| Mail | ↔ | Person |
| Mail | ↔ | Domain |
| Mail | ↔ | Account |
| Service | ↔ | Account |

## 注意事項

- **初回使用前に保管庫をバックアップしてください。** このプラグインは YAML frontmatter を直接変更します。ペアで定義されたプロパティのみを操作しますが、複雑なカスタム YAML がある場合、予期しないフォーマット変更が発生する可能性があります。
- **ファイルの削除** では、そのファイルを指すバックリンクは削除されません — これらは未解決リンクになります（偶発的なデータ損失を防ぐための設計上の選択です）。
- **ファイルのリネーム** は Obsidian の組み込みリンクアップデータが処理します — プラグインによる追加操作は不要です。
- **重複ペア**（例：`A ↔ B` と `B ↔ A`）は冗長です — 1 つのペアで双方向をカバーします。
- **重複するベース名** — 異なるフォルダに同名のファイルがあると、同期ターゲットが不正確になる可能性があります。一意のファイル名を使用してください。
- **システムプロパティ**（`title`、`aliases`、`tags`、`cssclasses`、`publish` など）はリレーションのプロパティとして使用できません。
